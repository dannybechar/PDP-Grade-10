# B1.1 — Canvas, Coordinates, and the Draw Loop

**Strategy document** | Unit B: Creative Programming | B1: The Draw Loop & Creative Environment

## Position and scope

B1.1 occupies two 45-minute lessons. The first establishes the canvas and coordinate system; the
second distinguishes one-time setup from repeated drawing. Together they create the lifecycle and
spatial model required by every later lesson.

1. **B1.1.1 — Canvas & Coordinate System**
2. **B1.1.2 — Setup vs. Continuous Draw**

## Learning objectives

Students should be able to:

- Configure a canvas in `settings()` using `size(width, height)`.
- Locate the origin and explain that x increases rightward while y increases downward.
- Interpret an ellipse's x/y position as its centre under Processing's default mode.
- Predict a shape's location from coordinates before running the sketch.
- Classify work as window configuration, one-time initialization, or repeated drawing.
- Explain how repeated `draw()` execution enables a sketch to update over time.

## Technical decisions

- `size()` is placed in `settings()` for the course's external-Java/BlueJ configuration.
- `setup()` is reserved for other one-time initialization.
- `draw()` repeats by default; this is a lifecycle rule, not a guarantee that a static program
  will animate.
- The canvas examples use `ellipse()` only as a coordinate marker. Other primitives and style
  controls remain in B1.2.
- A one-line increment may be demonstrated to make repetition visible, but constructing
  frame-based motion is deferred to B1.3.

## Lesson progression

### Canvas and coordinates

Students trace positions on a blank 400 × 400 grid, compare predictions with a running sketch,
then construct a canvas and place circles at specified coordinates. The task keeps size fixed so
that position is the only changing parameter.

### One-time and repeated execution

Students sort lines among `settings()`, `setup()`, and `draw()` and justify each placement by
lifecycle. A static sketch, a trail, and a background-cleared follower make repeated execution
visible without turning the lesson into a motion unit.

## Misconceptions to surface

- `(0, 0)` is the top-left of the canvas, not its centre.
- Positive y moves downward on the screen.
- `settings()`, `setup()`, and `draw()` do not all repeat.
- Repeated drawing alone does not create motion; some value or input must change.
- Omitting `background()` allows previous pixels to remain and can create a trail.

## Assessment evidence

Students predict coordinates, justify lifecycle placement, compile a complete sketch, and explain
the difference between a trail and a clean frame. Motion construction and unfamiliar-code tracing
are not assessed here because B1.3 and B1.4 own those skills.

## Implementation status

Implemented in `01-canvas-coordinates` and `02-setup-draw`. Both revised presentations use the
correct `settings()` lifecycle and include prediction, construction, and verification. All nine
supporting BlueJ projects compile independently against Processing 4.5.6.
