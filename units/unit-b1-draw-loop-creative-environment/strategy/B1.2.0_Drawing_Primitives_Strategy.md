# B1.2 — Drawing Primitives and Visual Parameters

**Strategy document** | Unit B: Creative Programming | B1: The Draw Loop & Creative Environment

## Position and scope

B1.2 turns coordinates into deliberate static compositions across two 45-minute lessons:

1. **B1.2.1 — Shapes & Geometry:** `rect()`, `ellipse()`, and `line()` with their position and
   size parameters.
2. **B1.2.2 — Color, Stroke & Fill:** persistent drawing style controlled by fill, stroke,
   weight, and omission commands.

Parameter changes in this learning statement are edit–compile–run comparisons. Per-frame
parameter change remains B1.3 content.

## Learning objectives

Students should be able to:

- Construct a composition using rectangles, ellipses, and lines.
- Distinguish `rect()`'s top-left reference point from `ellipse()`'s centre reference point.
- Interpret a line as two endpoints rather than a position plus width and height.
- Control fill, stroke colour, and stroke weight.
- Use `noFill()` and `noStroke()` deliberately.
- Predict the effect of changing one visual parameter before running the code.

## Technical baseline

- Under default modes, `rect(x, y, w, h)` uses `(x, y)` as the top-left corner and
  `ellipse(x, y, w, h)` uses it as the centre.
- `line(x1, y1, x2, y2)` is specified by two endpoints; fill has no effect on a line.
- Under Processing's default colour settings, one value is grayscale and three values are RGB.
- `fill()`, `stroke()`, and `strokeWeight()` set persistent style state for shapes drawn after
  the call, until that state is changed again.
- `rectMode()`, `ellipseMode()`, custom colour modes, transformations, and per-frame animation
  remain outside this lesson.

## Lesson progression

### Shapes and geometry

Students compare identical numeric arguments passed to `rect()` and `ellipse()`, trace several
mixed-primitive snippets, then reproduce a target containing at least one rectangle, ellipse,
and line.

### Colour, stroke, and fill

Students trace style state in execution order, compare grayscale with RGB, and reconstruct a
target that requires a filled shape, an unfilled shape, a stroked shape, and a shape with no
outline. Changing one value at a time keeps the code-to-output relationship observable.

## Misconceptions to surface

- Rectangle and ellipse coordinates do not use the same default reference point.
- A line has endpoints, not width and height.
- A style call is not permanently attached to the next shape; it remains active afterward.
- `fill()` cannot colour a line.
- `noFill()` and `noStroke()` change later drawing state; they do not erase existing pixels.

## Assessment evidence

Students predict positions and style changes, explain the active drawing state at selected lines,
and construct a static composition whose geometry and appearance match a supplied specification.
