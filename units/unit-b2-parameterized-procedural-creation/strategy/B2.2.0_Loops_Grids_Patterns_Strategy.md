# B2.2 — Loops, Grids, and Procedural Patterns

**Strategy document** | Unit B: Creative Programming | B2: Parameterized & Procedural Creation

## Position and scope

B2.2 applies counted loops to visual generation across three 45-minute lessons:

1. **B2.2.1 — Repeated Structures**
2. **B2.2.2 — Nested Loops & Grids**
3. **B2.2.3 — Procedural Patterns**

Students are not re-taught what a `for` loop is. The learning challenge is translating loop
variables into visual count, position, and other parameters.

## Learning objectives

Students should be able to:

- Replace repeated manual drawing calls with one counted loop.
- Trace the loop values that determine element count and spacing.
- Use one row loop and one nested column loop to generate a grid.
- Derive x from column and y from row without swapping the axes.
- Pass row/column-derived values into a reusable drawing method.
- Convert a uniform grid into a systematic procedural pattern with a traceable rule.

## Technical baseline

- Standard counted form: `for (int i = 0; i < count; i++)`.
- Positions use explicit formulas such as `start + i * spacing`.
- A two-dimensional grid uses separate `row` and `col` variables.
- The inner loop completes all columns for one row before the outer loop advances.
- Loop variables may control position, size, or grayscale, but every outcome must remain
  predictable from the code.
- Custom drawing methods from B2.1 remain the unit of repetition.
- Randomness, conditions, modulo, transformations, arrays, and input remain outside B2.2.

## Lesson progression

### Repeated structures

Students compare manual calls with one loop, trace the first and last iteration, calculate centre
positions, then construct an evenly spaced row whose final element remains on-canvas.

### Nested loops and grids

The class traces a small row-by-column table before drawing. Students name which variable controls
each axis, calculate selected coordinates, and build a complete grid from one nested structure.

### Procedural patterns

The grid structure stays fixed while a rule such as `15 + row * 8` or
`15 + row * 4 + col * 4` changes size systematically. Students distinguish a fixed value, a
one-axis rule, and a two-axis rule, then design a new traceable variation.

## Misconceptions to surface

- A loop bound controls how many iterations run; spacing controls where those results appear.
- Rows map to y and columns map to x in the course's grid convention.
- The inner loop must reset for each outer-loop iteration.
- A uniform grid is already a pattern; a procedural rule adds systematic variation rather than
  turning “not a pattern” into a pattern.
- A deterministic rule is not randomness.

## Assessment evidence

Students trace iteration tables, predict first/last coordinates, modify grid dimensions safely,
and construct a loop-generated pattern whose visual variation can be explained from row and column
values.
