# B2.3 — Controlled Randomness

**Strategy document** | Unit B: Creative Programming | B2: Parameterized & Procedural Creation

## Position and scope

B2.3 introduces Processing's random API and the design discipline around it across two 45-minute
lessons:

1. **B2.3.1 — Controlled Randomness**
2. **B2.3.2 — Regenerate & Compare**

The mechanism is not “make everything unpredictable.” Students deliberately select which values
may vary, choose safe bounds, and preserve a recognizable overall structure.

## Learning objectives

Students should be able to:

- Use `random(low, high)` and explain its lower-inclusive, upper-exclusive range.
- Recognize that `random()` returns a `float` and cast only when an integer is required.
- Choose safe bounds for position, size, and grayscale intensity.
- Separate properties controlled by a loop or fixed rule from properties selected randomly.
- Regenerate several results and describe precisely what changed and what stayed invariant.
- Design a generated composition with intentional fixed and variable features.

## Technical decisions

- Core examples use `random(low, high)` rather than an unbounded or full-range default.
- Position bounds account for the radius of the largest possible shape so elements do not clip.
- Colour examples remain grayscale; RGB tuples and the `color` type are unnecessary here.
- Generation occurs in `setup()` for a stable image during each run. Running again creates a new
  sample; placing random generation in continuously repeating `draw()` would introduce flicker
  and a different behaviour.
- Casting with `(int)` is ordinary Java syntax. Float values remain valid when the receiving API
  accepts them.
- Random seeds, probability distributions, movement, input, and animation are outside B2.3.

## Lesson progression

### Controlled ranges

Students trace a loop whose count remains fixed while x/y, size, or grayscale are sampled within
different bounds. They justify each range, then construct a row with fixed positions and random
sizes to demonstrate selective variation.

### Regenerate and compare

Students run the same program three times, record invariants and variations, and then design a
composition that deliberately preserves count and spacing while allowing selected properties to
change. Comparison is tied to a real construction task rather than being only a discussion.

## Misconceptions to surface

- The upper bound is not a possible result.
- A loop controls repetition; `random()` controls only the values assigned from it.
- Random position bounds of `0` to `width` can still clip a shape whose centre reaches an edge.
- Re-running the same algorithm can produce a different sample without changing the algorithm.
- Stability within one run requires deliberate lifecycle placement.

## Assessment evidence

Students annotate fixed and random expressions, justify numerical bounds, compare three runs, and
construct an output whose invariants and variations match a written design intention.
