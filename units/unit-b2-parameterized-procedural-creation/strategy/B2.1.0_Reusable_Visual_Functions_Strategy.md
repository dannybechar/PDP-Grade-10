# B2.1 — Reusable Visual Functions

**Strategy document** | Unit B: Creative Programming | B2: Parameterized & Procedural Creation

## Position and scope

B2.1 applies known method and parameter syntax to visual decomposition across three 45-minute
lessons:

1. **B2.1.1 — Reusable Visual Components**
2. **B2.1.2 — Parameters for Position**
3. **B2.1.3 — Combining Parameterized Properties**

The syllabus uses “custom function”; Java implements that idea as a method in the sketch class.
Student-facing explanations emphasize a named visual responsibility and configurable calls rather
than object-oriented method theory.

## Learning objectives

Students should be able to:

- Identify a group of drawing statements that forms one visual component.
- Move that group into a named `void` custom drawing method.
- Distinguish a method definition from a method call.
- Add x/y parameters so separate calls place the same component differently.
- Preserve geometric offsets relative to a supplied centre or anchor.
- Add a second configurable property such as size.
- Verify that a refactor changes code organization without unintentionally changing output.

## Technical decisions

- Lifecycle methods remain `public`; a student-authored drawing method may use no access modifier.
- Helper methods are defined at class level, outside `draw()`; Java does not permit nested method
  definitions.
- Part 1 uses a parameterless method to establish packaging. Its limitation is fixed coordinates,
  not duplicated implementation.
- Part 2 treats x and y together as one configurable property: position.
- Part 3 adds size as the primary second property. Appearance is optional because `fill()` changes
  persistent drawing state outside the helper as well.
- Methods are `void`; value-returning helpers, loops, randomness, conditions, recursion, and OOP
  design are outside B2.1.

## Lesson progression

### Package one responsibility

Students compare an inline flower with `drawFlower()`, trace call-and-return flow, predict what two
identical calls produce, and refactor a supplied balloon while keeping `background()` in `draw()`.

### Parameterize position

Hardcoded centres become `x` and `y`. Every petal or sub-shape is expressed as an offset from that
position so the component moves coherently when arguments change.

### Combine configurable properties

A size parameter is added without breaking position. Students call the same method several times
with deliberately varied position/size combinations and explain which argument controls each
visible property.

## Misconceptions to surface

- Calling a parameterless method twice does not duplicate its implementation, but both calls use
  the same hardcoded coordinates and therefore overlap.
- The semicolon belongs on a call, not after a method definition header.
- Closing braces must end `draw()` before the helper definition begins.
- Adding parameters requires coordinated changes to both the definition and every call.
- Refactoring is not verified merely because code compiles; the visual result must still match.

## Assessment evidence

Students complete three progressively independent refactors and explain the relationship among
definition, parameters, arguments, calls, and visible output.
