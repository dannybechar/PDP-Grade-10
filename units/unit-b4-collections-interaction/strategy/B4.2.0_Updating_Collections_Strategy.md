# B4.2 — Update Collections Over Time

**Strategy document** | Unit B: Creative Programming | B4: Collections & Interaction

## Position and scope

B4.2 extends B4.1’s parallel arrays from static data to changing state. The arrays retain fixed
capacity, while `activeCount` defines the packed active prefix. This avoids `ArrayList`, generics,
custom classes, and dynamic allocation while still allowing elements to move, expire, be removed,
and be added during execution.

The three 45-minute lessons are:

1. **B4.2.1 — Per-Frame Movement:** update every element using aligned velocity arrays.
2. **B4.2.2 — Lifespan and Removal:** introduce `activeCount`, backward traversal, and
   swap-and-pop removal.
3. **B4.2.3 — Addition and Synthesis:** claim the next free slot on a mouse event and combine
   addition, movement, lifespan, and removal.

## Central invariant

At all times:

```text
0 <= activeCount <= MAX_COUNT
```

Indices `0` through `activeCount - 1` contain fully initialized active elements. Indices from
`activeCount` onward are unused capacity. Every parallel array describes this same active prefix.

## Learning objectives

Students should be able to:

- Update every active position from its corresponding velocity each frame.
- Maintain a per-element lifespan countdown.
- Remove an element with swap-and-pop while copying every parallel property.
- Explain why backward traversal is safe with this removal technique.
- Combine independent removal triggers with a fresh boolean flag and separate `if` statements.
- Add a fully initialized element only when capacity is available.

## Technical decisions

- `MAX_COUNT` is fixed capacity; `activeCount` is changing membership.
- Removal copies the last active element into the removed slot, then decrements `activeCount`.
- A removal loop runs from `activeCount - 1` down to 0. Any element copied from a higher index was
  already processed earlier in that backward pass.
- Every parallel property must be copied during swap-and-pop; copying position alone corrupts the
  conceptual element.
- The removal flag is initialized to `false` inside each iteration. Separate conditions may set it
  to `true`, and one removal block runs afterward.
- Compound removal conditions are deliberately avoided in student-facing examples.
- Velocities remain positive-only to avoid the unintuitive distribution produced by casting
  negative random floats toward zero.

## Lesson progression

### B4.2.1 — Update, then render

The traversal mutates `yPositions[i]` from `yVelocities[i]` and renders the same index. Elements
that leave the canvas remain active in this lesson, deliberately motivating removal.

### B4.2.2 — Remove from the active prefix

For each active element, update position and lifespan, compute `shouldRemove`, and either render
or swap-and-pop. The class traces both forward and backward cases before implementing the safe
version.

### B4.2.3 — Initialize, then grow

`mousePressed()` first checks `activeCount < MAX_COUNT`, writes every property at index
`activeCount`, and only then increments the count. This ordering prevents the update loop from
seeing a partially initialized element. The synthesis begins with `activeCount = 0` and supports
safe no-op clicks when full.

## Misconceptions to surface

- Decreasing `activeCount` does not resize the arrays.
- Setting only a lifespan to zero does not remove an element from the active prefix.
- Forward traversal can skip a newly swapped-in element that has not yet been processed.
- Addition must initialize every property before incrementing `activeCount`.
- Loop bounds for active processing use `activeCount`, not `MAX_COUNT`.

## Verification checklist

- Empty and full states preserve the central invariant.
- Every addition is capacity-guarded and fully initializes one slot.
- Every removal copies all properties and decrements exactly once.
- Backward traversal is used whenever removal may occur.
- The boolean flag is reset for each element.
- Off-canvas and lifespan triggers cannot double-remove one element.
- No active loop reads index `activeCount`.
