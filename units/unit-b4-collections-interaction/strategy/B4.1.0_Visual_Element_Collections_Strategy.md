# B4.1 — Store and Iterate Over Visual Collections

**Strategy document** | Unit B: Creative Programming | B4: Collections & Interaction

## Position and scope

B4.1 introduces fixed-size Java arrays as the first collection mechanism in Unit B. Formal
object-oriented modelling, custom particle classes, `ArrayList`, imports, generics, and dynamic
resizing remain out of scope. Multi-property elements are represented with parallel arrays: the
same index across every array describes one visual element.

The three 45-minute lessons form a cumulative progression:

1. **B4.1.1 — Storing Many Elements in an Array:** declaration, allocation, zero-based indexing,
   `.length`, loop-based initialization, and loop-based drawing.
2. **B4.1.2 — Parallel Arrays:** several properties coordinated by one shared index and passed
   explicitly into a parameterized drawing method.
3. **B4.1.3 — Checking Collection Behaviour:** use the same traversal to compute information
   about the collection with a condition and local accumulator.

## Learning objectives

Students should be able to:

- Declare and allocate a fixed-size array and identify its valid indices.
- Bound traversal with `i < array.length`, distinguishing the `.length` field from a method call.
- Fill an array once in `setup()` and reuse the stored values in `draw()`.
- Preserve the shared-index invariant across parallel arrays.
- Pass one element’s coordinated properties into a reusable drawing method.
- Reset and update a local accumulator while checking every element.

## Technical baseline

- Java-mode Processing in a `PApplet` subclass; 400 × 400 canvas.
- `public void` on Processing lifecycle and event callbacks.
- `(int) random(low, high)` for integer samples; the upper bound is exclusive.
- Counted `for` loops, simple `if` statements, and parameterized helper methods are retrieved from
  earlier units rather than retaught.
- Arrays have fixed length and hold values of one declared type.
- Valid indices are `0` through `length - 1`.
- Array length is a field: `sizes.length`, not `sizes.length()`.
- B4.1 fully populates every array in `setup()`; `activeCount` is deferred to B4.2.

## Core examples and invariants

### B4.1.1 — One property per element

```java
int[] sizes = new int[20];

public void setup() {
  for (int i = 0; i < sizes.length; i++) {
    sizes[i] = (int) random(10, 40);
  }
}

public void draw() {
  background(255);
  for (int i = 0; i < sizes.length; i++) {
    ellipse(i * 19 + 20, 200, sizes[i], sizes[i]);
  }
}
```

The spacing matches the revised presentation and keeps twenty centres within the 400-pixel
canvas. Random values are initialized once, so the visual arrangement remains stable while the
window is open.

### B4.1.2 — Parallel properties

All arrays use one `COUNT`, and every property for element `i` is read with that same `i`:

```java
final int COUNT = 20;
int[] xPositions = new int[COUNT];
int[] yPositions = new int[COUNT];
int[] sizes = new int[COUNT];
```

Positions use safe centre ranges such as `(int) random(20, 380)`. Equal lengths are necessary but
not sufficient: index alignment is a semantic invariant maintained by the programmer.

### B4.1.3 — Checking during traversal

`largeCount` is initialized inside `draw()`, before the loop, so each frame recomputes the count
instead of accumulating indefinitely. `text(...)` and String concatenation display the computed
result; students have already encountered text in B3 scene projects, so the new idea here is the
collection-level accumulator rather than the display API.

## Misconceptions to surface

- An array of length 20 does not have an index 20.
- `.length()` does not compile for arrays.
- Parallel arrays do not automatically stay semantically aligned.
- Random initialization in `draw()` would replace stored values every frame.
- A count intended to describe the current frame must be reset before traversal.

## Assessment evidence

Each lesson uses prediction, hand tracing, guided modification, and an independent construction.
The final evidence is a program that stores coordinated element properties, draws every element,
and computes at least one collection-level result without repeated per-element code.
